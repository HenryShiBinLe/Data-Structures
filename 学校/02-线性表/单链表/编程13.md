# 编程13 链表去重

> 7-2　链表去重　｜　分数 25
> 作者：陈越　｜　单位：浙江大学

给定一个带整数键值的链表 L，你需要把其中绝对值重复的键值结点删掉。即对每个键值 K，只有第一个绝对值等于 K 的结点被保留。同时，所有被删除的结点须被保存在另一个链表上。例如给定 L 为 21→-15→-15→-7→15，你需要输出去重后的链表 21→-15→-7，还有被删除的链表 -15→15。

## 输入格式

输入在第一行给出 L 的第一个结点的地址和一个正整数 N（≤10⁵，为结点总数）。一个结点的地址是非负的 5 位整数，空地址 NULL 用 -1 来表示。

随后 N 行，每行按以下格式描述一个结点：

```
地址 键值 下一个结点
```

其中 `地址` 是该结点的地址，`键值` 是绝对值不超过 10⁴ 的整数，`下一个结点` 是下个结点的地址。

## 输出格式

首先输出去重后的链表，然后输出被删除的链表。每个结点占一行，按输入的格式输出。

## 输入样例

```
00100 5
99999 -7 87654
23854 -15 00000
87654 15 -1
00000 -15 99999
00100 21 23854
```

## 输出样例

```
00100 21 23854
23854 -15 99999
99999 -7 -1
00000 -15 87654
87654 15 -1
```

## 思路要点

- **静态链表 = 数组当内存，下标当地址**：地址是 5 位非负整数，直接拿地址当下标，`arr[addr]` 一步就能找到结点。`next` 里存的是下一个结点的**下标**，`-1` 表示空，相当于指针链表的 `NULL`。
- **两个数组、同一套下标**：`arr` 存原链表，`arr_D` 存删除链表。被删的结点复制到 `arr_D` 的**同一个下标**上（地址不变，输出时要原样打印）。
- **`LNodeMov` 传的是前驱**：单链表删结点必须站在前一个结点上，所以参数 `addr` 是"要删的结点的前一个"。函数里一共做四件事：
  1. 把新结点接到删除链表上：尾巴 `to[*tail].next` 指向它；如果这是第一个被删的结点，就记下 `*head_D`
  2. 把结点复制进 `to`，它的 `next` 设成 `-1`（它现在就是尾巴）
  3. 从原链表中摘掉：前驱的 `next` 跳过它
  4. 更新尾巴 `*tail`
- **去重的判断：值当下标**：`seen[abs(data)]` 每遇到一次就加 1，加完之后 `> 1` 就说明不是第一次出现，删掉。键值绝对值 ≤ 10⁴，辅助数组 O(值域)，整体 O(N)。对应讲义 [[408数据结构讲义/教材-fable5/专题-去重]] 的"思路③"。
- **删完之后前驱不动**：删除分支里不更新 `tmp_prior`，只有保留时才执行 `tmp_prior = cur`。`cur = arr[cur].next` 两种情况都照常执行，因为 `LNodeMov` 改的是前驱的 `next`，被删结点在 `arr` 里仍然记得原来的后继。
- **输出格式**：地址用 `%05d` 补零。`next` 为 `-1` 时用 `%d` 原样打印（`%05d` 会打印成 `-0001`）。键值用 `%d`，不补零。详见 [[C语言基础/补充-printf格式控制]]。
- **和 408 真题的关系**：408 有一道"单链表保存 m 个整数，|data| ≤ n，保留绝对值第一次出现的结点"的真题，和本题本质相同，只是换成了指针链表。循环骨架一样，`cur = arr[cur].next` 对应 `p = p->next`。

## 踩过的坑（2026-09-26）

**静态链表本身**

1. **以为 `-1` 存不进去**：误以为 `next` 存 `-1` 需要数组里有第 -1 格。其实 `-1` 只是 `next` 字段里的一个**值**，存完全没问题。危险的是拿它去**访问** `arr[-1]`，所以访问前一定要先判断 `!= -1`，和指针版先判 `!= NULL` 是同一回事。
2. **以为把删除链表连起来需要双链表**：静态链表里"A 连到 B"就是**往 A 的 `next` 里写 B 的下标**，一次赋值。`tail` 记住最后一个结点的下标，直接 `to[tail].next = 新结点`，不需要往回走，也就不需要 `prior`。双链表的 `prior` 是为了从任意结点往回走，这里只在尾部追加，用不上。
3. **改错了数组**：写成了 `from[*tail].next`，但 tail 所在的链表存在 `to` 里。程序不崩溃，删除链表却悄悄少了结点。**用两个数组时，每写一次 `xxx[...]` 都要问一句：这个结点现在归哪个数组管？**
4. **head 是干什么的**：`tail` 负责"下次连在谁后面"，`head_D` 负责"输出时从哪开始走"，只在删第一个结点时写一次。初值 `-1` 表示空链表，这样一个都没删时输出循环会直接结束。
5. **删完之后前驱被错误地往前挪**：`tmp_prior = cur` 原来不管删没删都会执行。连续删除时，下一次会去改一个已经被删掉的结点的 `next`。**题目样例里没有连续删除，所以用样例测不出来**，要用 `21 → -15 → -15 → 15` 这种数据才能暴露。

**C 语言基本功**

6. **数组传进函数本来就能改**：数组名传参时退化成首元素地址，函数里改 `arr[i]` 就是改原数组，不用加 `&`。要注意的是形参的**元素类型**要写对（一开始写成了 `int arr[]`，实际是 `LNode`）。
7. **数组大小差 1**：`LNode arr[99999]` 的合法下标是 0 ~ 99998，放不下地址 99999，而样例里正好就有 99999。**下标要取到 M，数组就要开 M+1。**
8. **漏写解引用**：`head_D = addr_next` 改的是指针自己，不是 main 里的变量，要写 `*head_D`。编译器提示"加 `&`"，但照着改能编译通过，意思却是错的。**编译器只管类型对不对得上，不管你想干什么。**
9. **座位号选错**：一开始写的是 `seen[cur]`，拿地址当座位号。地址两两不同，永远查不出重复。**座位号应该是"判断重复的依据"**，本题就是 `abs(data)`。
10. **"查"和"标"的顺序**：两个独立的 `if` 写成了"只有等于 0 才加 1"，计数永远到不了 2，`LNodeMov` 一次都不会被调用。后来自己想出"每次都加 1，加完 > 1 就删"，比 if / else 更简单。
11. **`abs` 在 `<stdlib.h>`**：不知道的库函数就用 `man 3 函数名` 查，SYNOPSIS 里写着头文件和函数原型。

**输出与环境**

12. **补零**：`%05d` 表示至少占 5 格，不够的补 0。但负号也占一格，`-1` 会打印成 `-0001`，所以 `next` 要分情况打印。
13. **样例过了 ≠ 对了**：第三列一开始用 `%d`，样例恰好全是没有前导零的地址，所以能过。换一组 `next` 为 `00000` 的数据就会打印成 `0`，OJ 判 WA。**要自己造边界数据测。**
14. **编译产物别叫 `test`**：`test` 是 shell 的内置命令，只输入 `test` 不会运行你的程序，什么都不输出。要写 `./test`，或者干脆换个名字。
