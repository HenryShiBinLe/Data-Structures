# 编程21 中缀表达式转换为后缀表达式

> 7-2　中缀表达式转换为后缀表达式　｜　分数 30
> 作者：吴敏华　｜　单位：首都师范大学

输入一行字符表示中缀表达式，表达式中运算对象是单个字母或个位数字，运算符有 `+`、`-`、`*`、`/`、`%`，中缀表达式中可以有圆括号。运算对象是变量和常数，变量用一个字母表示，常量是个位整数。

## 输入格式

输入在一行中给出一个中缀表达式。

## 输出格式

输出对应的后缀表达式。

## 输入样例

```
(a+b)*c
```

## 输出样例

```
ab+c*
```

# 复盘：这道题要带走的东西

代码见 [[21.cpp]]。这道题最值得带走的不是代码，而是**怎么把一团乱麻捋成一张表**。

## 最终规则

| 读到 | 栈顶 | 做法 |
|---|---|---|
| 字母/数字 | 任意 | 直接输出（运算对象顺序不变，只有运算符往后挪） |
| `(` | 任意 | 不比较，直接进栈（插一块隔板，等价于栈底） |
| `)` | 任意 | 不进栈；一直弹栈输出，直到遇到 `(`；`(` 弹出但不输出 |
| 运算符 | 空 或 `(` | 直接进栈（`(` 当作栈底） |
| 高级 `*/%` | 低级 `+-` | 直接进栈，压在上面 |
| 低级 `+-` | 高级 `*/%` | **全弹**（弹到栈空或 `(` 为止），新来的再进栈 |
| 运算符 | 同级 | 弹出一个，新来的进栈 |
| 读完整行 | — | 栈里剩下的按栈的顺序全部弹出输出 |

同级只弹一个就够：没有括号时栈最多两层 `[ + * ]`，同级不会堆积。

例：`a+b*c+d` → `abc*+d+`。读到第二个 `+` 时栈是 `[ + * ]`，按"低级碰高级"全弹，`*`、`+` 依次出栈，`+` 再进栈。

合成一句话：**新来的运算符优先级不比栈顶高，栈顶就弹出；一直比下去，直到栈顶比它低、遇到 `(` 或栈空，再把它压进去。**

类比：栈是一个**候场区**。运算对象一到就上台；运算符在候场区等，等到后面来了一个级别不比它高的，说明它右边的运算对象已经齐了，就轮到它上台。括号是候场区里临时隔出的小房间，房间里的事办完（读到 `)`），房间就拆掉。

## 分支顺序：`else if` 链是一层层的筛子

一个字符从顶上掉下来，**被哪一层接住，就只在那一层处理**，下面的层完全看不到它。排顺序就是在问：每种字符想让哪一层接住？有没有别的层抢在前面把它截走？

| 层 | 接住什么 | 只看新字符，还是还要看栈顶 | 为什么放在这里 |
|---|---|---|---|
| 1 | 字母/数字 | 只看新字符 | 不管栈是什么样都直接输出，最先筛掉 |
| 2 | `)` | 只看新字符 | 只有一种做法；**必须**在第 3 层之前，否则会被 `top=='('` 截走 |
| 3 | 栈空 / 新来 `(` / 栈顶是 `(` | 新字符和栈顶都看 | 这几种都"不用比较，直接进栈" |
| 4 | 栈顶低、新来高 | 比较优先级 | 走到这里，栈顶一定是真正的运算符 |
| 5 | 栈顶高、新来低 | 比较优先级 | 弹到 `(` 或栈空 |
| else | 同级 | | 上面全排除以后只剩这一种 |

三条原则：

1. **只看新字符就能决定的，放前面。**
2. **越特殊的越往前，越笼统的越往后。** 宽条件放前面会截走别人的情况。
3. **`else` 是剩下的所有情况。** 写之前必须确认真的只剩一种。

踩过的坑，都是顺序问题：

- `(a+b)` 输出里多一个 `(`：没有接住"栈顶是 `(`"的层，它掉进了 else（原则 3）
- `a*(b)+c` 里 `)` 被压进栈：第 3 层的宽条件排在 `)` 前面，把 `)` 截走了（原则 2）

**自检方法**：写完以后，把每一种可能的输入（字母、`(`、`)`、运算符 × 各种栈顶）挨个拿出来，从上往下问："它第一个满足的是哪一层？是我想让它去的那层吗？"

## 怎么才能想得全面

没有人能一次想全，这道题也是一轮轮补出来的。能做到的是让遗漏**少一点、早一点被发现**：

1. **列"维度 × 维度"的表，不靠脑子记。** 新来的字符（字母、`(`、`)`、运算符）× 栈顶（空、`(`、低级、高级）。表里空着的格子就是漏掉的情况。
2. **能合并的情况尽量合并。** `(` 当栈底，并进"栈空"；同级加减弹一个和弹到底效果一样；规则合成一句"一直弹"。情况越少越不容易漏。（教材的标准写法把优先级写成数字，用循环比较，分支更少，回头看教材"表达式求值"一节可以对照。）
3. **专门构造边界例子。** 固定问法：最短的输入是什么？嵌套最深是什么？两个特殊情况撞在一起会怎样？这次是 `a*(b)+c`、`((a+b))` 找出了 bug。

## 抽丝剥茧的过程

| 步骤 | 做了什么 | 方法 |
|---|---|---|
| 1 | 样例上下对齐，发现字母顺序不变，只有运算符在动 | **观察输入输出差异**，缩小问题：只研究运算符 |
| 2 | 先不管括号 | **去掉复杂因素**，先解决简化版 |
| 3 | 用 `a+b*c` 和 `a*b+c` 手动走一遍 | **最小例子手动模拟**，从结果里找规律 |
| 4 | "平时是队列，有括号才是栈"、"乘法来了全弹空"都被反例推翻 | **用反例检验直觉** |
| 5 | 统一成"新来的和栈顶比"，列成表 | **统一视角**，再列表穷举 |
| 6 | 括号加回来：`(` 等于栈底，`)` 是弹栈信号 | **把复杂因素加回来**，复用已有规则，不另起一套 |
| 7 | 表格翻译成 `else if` 链，抽出 `PopPrintf` | **表格对应代码**，重复动作抽成函数 |
| 8 | 跑边界例子，发现分支顺序问题 | **测试找 bug**，回到表格找原因 |

一句话：**先缩小、再简化、用小例子找规律、用反例检验、列表穷举、最后把复杂因素加回来。**
