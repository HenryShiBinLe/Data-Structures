# 严蔚敏顺序栈的基本约定

配合 [[19.cpp]] 使用。自己的版本在 [[练习/栈与队列/栈/SQstack/stack.c|stack.c]]。

## 结构体：三个成员

严蔚敏版的顺序栈用两个指针加一个容量来描述。数组本身由 `malloc` 动态分配，不写在结构体里。

```c
typedef struct {
    SElemType *base;   // 栈底指针：指向 malloc 得到的那块内存的第 0 格，固定不动
    SElemType *top;    // 栈顶指针：上下移动
    int stacksize;     // 当前已分配的容量（能放几个元素），不是元素个数
} SqStack;
```

| 成员 | 类型 | 含义 | 会变吗 |
| --- | --- | --- | --- |
| `base` | `SElemType *` | 整块存储区的起点（栈底） | 只在 `realloc` 扩容时可能变 |
| `top` | `SElemType *` | 栈顶元素的**上一格**（见下一节） | 每次 Push/Pop 都变 |
| `stacksize` | `int` | 当前分配了多少格 | 只在扩容时变 |

## 核心约定：top 永远指向空位

**top 指向栈顶元素的上一格，也就是下一个元素要放进去的位置。** 其他所有判断和操作都是从这一条推出来的。

```text
放了 3 个元素，容量 stacksize = 5：

  下标:   0      1      2      3      4
       [ 10 ] [ 20 ] [ 30 ] [    ] [    ]
         ↑                    ↑
        base                 top        ← top 指的是空格，不是 30

空栈：
       [    ] [    ] [    ] [    ] [    ]
         ↑
     base = top
```

类比：一摞盘子。`base` 是托盘底，位置固定；`top` 是一根**悬在最上面那个盘子正上方**的手指，指着下一个盘子要放的位置，而不是按在最上面那个盘子上。

依据：题目里 Push 扩容后写的是 `s.top = s.base + s.stacksize`。栈满时下标 0 到 stacksize-1 都有元素，`base + stacksize` 正好是最后一个元素的上一格。

## 由约定推出的三个判断

两个同类型的指针相减，得到的是它们之间隔了**几个元素**，所以 `top - base` 就是当前栈里的元素个数。

| 判断 | 写法 | 为什么 |
| --- | --- | --- |
| 元素个数 | `top - base` | base 到 top 之间的格子都放了元素 |
| 空栈 | `top == base` | 一个元素都没有，空位就是第 0 格 |
| 栈满 | `top - base >= stacksize` | 元素个数已经达到分配的容量 |

初始化（InitStack）就是把栈摆成空栈：分配一块内存，让 top 和 base 重合，并把 stacksize 设为**刚才分配了多少格**。

## 和自己的 SQstack 对照

两个版本只差一件事：我的 top 按在栈顶元素上，严版的 top 悬在栈顶元素的上一格。

| | 我的版本 | 严蔚敏版 |
| --- | --- | --- |
| top 的类型 | `int` 下标 | `SElemType *` 指针 |
| top 指向 | 栈顶元素本身 | 栈顶元素的上一格（空位） |
| 空栈 | `top == -1` | `top == base` |
| 元素个数 | `top + 1` | `top - base` |
| 容量 | 宏 `maxsize`，固定 | `stacksize`，可以扩容 |
| 栈满 | `top == maxsize - 1` | `top - base >= stacksize` |
| 栈满时 | 报错退出 | `realloc` 多分配 `STACKINCREMENT` 格 |
| 存储区 | 结构体里的数组 | `malloc` 出来的一块内存 |
| 传参 | `sqstack *`，用 `->` | C++ 引用 `SqStack &s`，用 `.` |

## 留给自己推的三个操作

只用一条规则去推：**操作前 top 指空位，操作后 top 还得指空位。** 先在上面那张内存图上画一遍再填。

| 操作 | 要想清楚的问题 | 我的答案 |
| --- | --- | --- |
| Push | 新元素应该写在哪一格？写完以后哪一格才是新的空位？先写还是先移？ | |
| Pop | 真正的栈顶元素在 top 的哪一边？拿走以后哪一格变成空位？先移还是先读？ | |
| GetTop | 和 Pop 读的是同一格，但 top 能不能动？ | |

提示：可以拿自己版本的顺序做对照。我的版本 Push 是「先移后写」，Pop 是「先读后移」。top 的位置上移了一格，顺序会怎么变？

## 易错点

1. **指针加减不要乘 sizeof。** `int *p` 的 `p + 1` 已经是往后移 1 个 int（4 字节），写成 `p + sizeof(int)` 就会移 4 个 int。`sizeof` 只在 `malloc`/`realloc` 里用，因为它们只认字节数。
2. **`stacksize` 不是元素个数。** 它是当前分配了多少格，相当于我版本里的 `maxsize`。元素个数永远用 `top - base` 算。
3. **不能直接用 `*top` 取栈顶。** top 指的是空格，`*top` 读到的是一个没放过东西的垃圾值。
4. **`realloc` 以后 top 要重新算。** 扩容可能把整块数据搬到新地址，旧的 top 就指向了已经释放的内存，所以题目里用 `base + stacksize` 重新定位。
